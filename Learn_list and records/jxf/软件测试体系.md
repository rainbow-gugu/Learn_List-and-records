### 2.1 测试关注维度

软件测试从多个维度验证产品质量：

- **功能正确性**：功能是否符合需求规格
- **完整性**：是否覆盖所有业务场景和边界条件
- **安全性**：是否存在漏洞、权限越界、数据泄露风险
- **质量**：性能、可用性、可维护性等非功能指标

### 2.2 测试分级（V 模型）

测试从粒度到范围分为四个层级，对应不同的执行人员：

| 测试层级     | 测试对象          | 执行人员  | 目标          |
| -------- | ------------- | ----- | ----------- |
| **单元测试** | 最小可测试单元（方法/类） | 开发人员  | 验证每个单元逻辑正确  |
| **集成测试** | 模块间接口与交互      | 开发人员  | 验证模块组装后协同工作 |
| **系统测试** | 整个系统          | 测试人员  | 验证系统整体符合需求  |
| **验收测试** | 交付产品          | 客户/用户 | 确认产品满足验收标准  |

### <span style="color:#3b82f6">2.3 测试方法分类</span>

| 方法 | 核心思想 | 特点 |
|------|---------|------|
| **白盒测试** | 基于代码内部结构设计用例 | 关注逻辑覆盖、路径覆盖，单元测试常用 |
| **黑盒测试** | 不关注内部实现，只验证输入输出 | 关注功能正确性，系统/验收测试常用 |
| **灰盒测试** | 白盒与黑盒结合 | 部分了解内部结构，集成测试常用 |

## <span style="color:#2563eb">三、JUnit 单元测试框架</span>

JUnit 是 Java 生态最主流的单元测试框架，提供注解驱动的测试规范和断言机制。

### <span style="color:#3b82f6">3.1 基本规范</span>

- 测试方法使用 `@Test` 注解标记
- 测试方法签名为 `public void`，无参数
- 测试类通常以 `XxxTest` 命名，与被测类对应
- 每个测试方法独立执行，互不影响

### <span style="color:#3b82f6">3.2 断言机制</span>

JUnit 通过断言（Assert）验证实际结果是否符合预期：

- `assertEquals(expected, actual)`：断言相等
- `assertTrue(condition)`：断言条件为 <span style="color:#d97706">true</span>
- `assertFalse(condition)`：断言条件为 false
- `assertNull(obj)`：断言对象为 null
- `assertNotNull(obj)`：断言对象非 null

> <span style="color:#d97706">断言是单元测试的核心：每个测试方法至少包含一个断言，验证被测代码的输出是否符合预期。</span>

## <span style="color:#2563eb">四、WAR 包</span>

**WAR（Web Application Archive）** 是 Java Web 应用的打包格式，扩展名为 `.war`。

| 对比项 | JAR | WAR |
|--------|-----|-----|
| 用途 | 普通 Java 程序/类库 | Java Web 应用 |
| 运行方式 | `java -jar` | 部署到 Servlet 容器（Tomcat） |
| 目录结构 | 普通 class 文件 | 含 `WEB-INF/` 标准 Web 目录 |

WAR 包内部包含网页、静态资源（CSS/JS/图片）、编译后的 class 文件以及依赖的 JAR 包，部署到 Tomcat 的 `webapps/` 目录后自动解压运行。
